# Граф денег

Инструмент для AML-аналитика: по выгрузке исходящих переводов известных клиентов на несколько колен восстанавливает структуру финансовой сети и отвечает на вопрос «кого из этих клиентов смотреть первым и почему». В репозитории — выгрузка организаторов (81 seed, 4 колена, 2 248 узлов), она открывается по умолчанию; свою выгрузку аналитик загружает на экране «Данные», и пайплайн пересчитывает роли за несколько секунд.

> Кейс HackAlem AI «Граф денег: восстановление финансовой структуры организованной группы по транзакционной сети». Требования к README — в [docs/README_REQUIREMENTS.md](docs/README_REQUIREMENTS.md).

## Как работает решение

1. **Пайплайн** (`pipeline/run.py`, Python) читает три `.parquet` (`nodes`, `edges`, `transactions`; по умолчанию из `task/data/`, любой другой каталог — `--data`), считает метрики узлов (степени, суммы, коэффициент пропуска, seed-деньги, посредничество, циклы, быстрый вывод, синхронные входы), каскадом правил с явными порогами назначает одну из 6 ролей, находит кластеры (Louvain, на неориентированном графе) и считает `priority_score`. Пересчёт от parquet до CSV — одна команда, несколько секунд:

   ```bash
   cd pipeline && uv sync && uv run python run.py
   ```

2. **Выход** в `out/` (или `--out`): `nodes_roles.csv` (строка на каждый узел входа, для выгрузки организаторов — ровно 2 248, и 6 колонок схемы ТЗ: `gid, role, role_score, cluster_id, priority_score, evidence`), `clusters.csv`, `top_nodes.csv`; все метрики узлов — в `node_metrics.csv` и `node_metrics.json`, метрики рёбер — в `edge_metrics.csv`.
3. **Сервер** (Bun + Hono) держит несколько выгрузок, одна активна: встроенная «демо» (`task/data` + `out/`) и загруженные через `POST /api/datasets`. Загрузку он сохраняет в `data/datasets/<id>/raw/`, запускает `pipeline/run.py` подпроцессом, читает результат и делает выгрузку активной. Все остальные маршруты отдают граф, роли, кластеры и аналитику активной выгрузки.
4. **Клиент** (React) показывает результат: обзор, схему сети, приоритеты, кластеры, карточку узла, аналитику, AI-ассистента, правила ролей, схему решения, скачивание трёх CSV и экран «Данные» для загрузки своей выгрузки и переключения между выгрузками (меню в шапке). Клиент и сервер роли не пересчитывают — только пайплайн.

Все выводы сформулированы как гипотезы для проверки, а не утверждения о причастности. Правила и пороги — [pipeline/RULES.md](pipeline/RULES.md), подробности запуска и проверки — [pipeline/README.md](pipeline/README.md).

## Технологии

| Часть | Стек |
|---|---|
| Сервер | Bun, Hono, hyparquet (чтение parquet, ZSTD через встроенный `Bun.zstdDecompressSync`), d3-force (раскладка графа при старте) |
| Клиент | Vite, React 19, React Router 8, TypeScript, Tailwind CSS v4, shadcn/ui (Base UI), Canvas 2D для схемы сети; шрифты Unbounded, IBM Plex Sans/Mono (Google Fonts) |
| Монорепо | bun workspaces: `client/`, `server/` |

## Архитектура

```
task/data/*.parquet + out/ (демо) ─┐
                                    ├─► server/ (Bun + Hono, :3001) ──/api──► client/ (Vite + React, :5173)
data/datasets/<id>/{raw,out} ───────┘         │ POST /api/datasets → pipeline/run.py (подпроцесс) ─┘
```

```
server/src/
  index.ts        точка входа Bun (порт 3001, env PORT)
  app.ts          Hono-приложение: /api, JSON 404 для неизвестных /api/*, JSON 500; остальные пути — client/dist и SPA-фолбэк index.html
  routes/index.ts все маршруты API в одном месте, экспорт AppType для Hono RPC
  routes/*.ts     health, stats, graph, transactions, nodes, analytics, assistant, results (top, clusters, meta, export),
                  datasets (список, загрузка, активация, удаление выгрузок)
  data/store.ts   реестр выгрузок и активная выгрузка: «demo» из DATA_DIR + OUT_DIR, остальные из DATASETS_DIR
  data/dataset.ts загрузка одной выгрузки: parquet + out/ + раскладка d3-force + аналитика + инструменты
  data/load.ts    чтение трёх parquet каталога
  data/results.ts чтение node_metrics.json, clusters.csv, top_nodes.csv и раскладка графа
  data/analytics.ts  маршруты, циклы, время, аномалии, устойчивость, полнота (считаются при загрузке выгрузки)
  data/tools.ts   детерминированные инструменты запросов к графу (для ассистента и UI)
  data/types.ts   типы строк parquet

client/src/
  router.tsx      таблица маршрутов (React Router, createBrowserRouter)
  layouts/        общий каркас (навигация, поиск по gid) и вкладки разделов «анализ» и «метод»
  pages/          Обзор, Схема сети, Карточка узла, Приоритеты, Кластеры, анализ (Маршруты, Время, Аномалии,
                  Устойчивость, Полнота), Ассистент, метод (Правила ролей, Схема решения), Данные (загрузка), 404
  components/kit.tsx  общие элементы дизайна: роли и их цвета, заголовки, панели, gid-ссылки, шкалы
  lib/api.ts      типизированные запросы к /api
  lib/format.ts   форматирование чисел и сумм (ru-RU)
```

- gid везде хранятся строками: значения вида `100000003684369100` больше `Number.MAX_SAFE_INTEGER`.
- В режиме разработки Vite проксирует `/api` на `:3001`.

### Страницы

| Путь | Что показывает |
|---|---|
| `/` | обзор: масштаб выгрузки, распределение ролей, колена обхода, первые в очереди, ловушки данных, скачивание CSV |
| `/graph` | схема сети на canvas: раскраска по роли / колену / кластеру, фильтр ролей, поиск gid, карточка выбранного узла; `?q=<gid или хвост>`, `?cluster=<id>` |
| `/nodes/:gid` | карточка узла: роль и почему (evidence, порог ↔ факт), движение денег, метрики, циклы, синхронные входы, все рёбра |
| `/top` | топ приоритетов с обоснованием `why` |
| `/clusters` | кластеры: состав ролей, гипотеза, крупнейшие узлы |
| `/analysis/routes` | повторяющиеся цепочки A→B→C и простые циклы ≤ 5 |
| `/analysis/time` | активность по дням, синхронные входы, сквозной транзит |
| `/analysis/anomalies` | вход «не по колену»: z-оценка log(входа) внутри своего колена обхода |
| `/analysis/resilience` | что будет со связностью при изъятии топ-N по приоритету |
| `/analysis/completeness` | белые пятна выгрузки и рекомендуемые запросы в банк |
| `/assistant` | AI-ассистент: вопрос → вызовы детерминированных инструментов → ответ со ссылками на gid |
| `/method/rules` | правила ролей и приоритета с порогами из выгрузки пайплайна |
| `/method/architecture` | схема решения: parquet → пайплайн → out/ → сервер → интерфейс |
| `/upload` | «Данные»: загрузка своих `nodes`, `edges`, `transactions` (.parquet), запуск пайплайна, сводка результата и лог, список выгрузок с переключением и удалением |
| `/analysis`, `/method`, `/rules` | перенаправления на первую вкладку раздела и на `/method/rules` |

### API

| Метод | Ответ |
|---|---|
| `GET /api/health` | `{ ok: true }` |
| `GET /api/stats` | активная выгрузка (`datasetId`, `datasetName`), число узлов, рёбер, транзакций, seed, общий оборот, период, число колен `maxDepth`, узлы по коленам, минимальная сумма перевода, число узлов по ролям и кластеров |
| `GET /api/graph` | `{ nodes, edges }`; у узлов координаты `x, y`, роль, приоритет, кластер |
| `GET /api/transactions` | все транзакции с датами |
| `GET /api/nodes/:gid` | узел + метрики пайплайна + входящие и исходящие рёбра; 404 для неизвестного gid |
| `GET /api/top` | `top_nodes.csv` + метрики узлов |
| `GET /api/clusters` | `clusters.csv` + число узлов каждой роли в кластере |
| `GET /api/meta` | пороги правил, веса ролей, число узлов по ролям (`_meta` из `node_metrics.json`) |
| `GET /api/export/:file` | скачивание `nodes_roles.csv`, `clusters.csv`, `top_nodes.csv` |
| `GET /api/analytics/:key` | `time`, `routes`, `anomalies`, `resilience`, `completeness`: считаются при загрузке выгрузки из parquet и `out/` |
| `GET /api/datasets` | `{ active, datasets[] }`: id, имя, источник (`bundled`/`upload`), размеры, число колен, период, роли |
| `POST /api/datasets` | multipart `nodes`, `edges`, `transactions` (.parquet) и необязательное `name` → запуск пайплайна; 200 `{ dataset, log }` и выгрузка активна; 400 `{ error, log }` с сообщением пайплайна (`ОШИБКА ВХОДНЫХ ДАННЫХ: …`); лимит 100 МБ, одна загрузка за раз |
| `POST /api/datasets/:id/activate` | сделать выгрузку активной |
| `DELETE /api/datasets/:id` | удалить загруженную выгрузку (демо удалить нельзя); если она была активна, активной становится демо |
| `GET /api/assistant/status` | настроен ли LLM, модель, список инструментов |
| `POST /api/assistant/tools/:name` | детерминированный инструмент: `node_metrics`, `neighbors`, `common_successors`, `paths`, `sync_events`, `query_nodes`, `cluster_summary` |
| `POST /api/assistant/ask` | `{ question }` → ответ модели и цепочка вызовов инструментов |

Все маршруты, кроме `datasets` и `health`, относятся к активной выгрузке. Маршруты top, clusters, meta, export и analytics возвращают 503, если у неё нет выгрузки пайплайна. Неизвестный путь под `/api/` — JSON `{ "error": "not found" }` с кодом 404.

## Установка и запуск

Нужен [Bun](https://bun.sh) ≥ 1.4.

```bash
bun install
bun run dev
```

Клиент: http://localhost:5173, API: http://localhost:3001. Демо-выгрузка берётся из `task/data` (`DATA_DIR`) и `out/` (`OUT_DIR`); без `out/` маршруты ролей отвечают 503. Загруженные выгрузки лежат в `data/datasets/` (`DATASETS_DIR`, в git не попадает) и подхватываются при следующем старте. Для загрузки через интерфейс серверу нужен `uv` в PATH: он запускает `pipeline/run.py` подпроцессом (см. ниже). Формат выгрузки пайплайна — [docs/PIPELINE_CONTRACT.md](docs/PIPELINE_CONTRACT.md).

### Пайплайн (Python)

Роли, кластеры, приоритет и три CSV по ТЗ считает `pipeline/run.py` — одна команда, ~4 с:

```bash
cd pipeline && uv sync && uv run python run.py
```

Другая выгрузка тех же трёх parquet (схема — `task/README.md`): `uv run python run.py --data /путь/к/каталогу --out /путь/для/результата`. Число колен и период пайплайн берёт из данных; ошибки схемы печатаются строкой `ОШИБКА ВХОДНЫХ ДАННЫХ: …`.

Правила ролей с источниками порогов — [pipeline/RULES.md](pipeline/RULES.md); запуск, проверка (синтетический тест, детерминизм, чувствительность, симуляция жюри), ограничения и масштабирование — [pipeline/README.md](pipeline/README.md).

Если порты заняты другой копией проекта, сервер и прокси клиента переназначаются переменными:

```bash
cd server && PORT=3002 bun run dev
cd client && API_PROXY=http://localhost:3002 bunx vite --port 5180
```

## Данные и интеграции

Датасет организаторов (обезличенный), папка `task/data/`:
- `edges.parquet` — 3 119 пар плательщик → получатель, агрегировано за июль 2026;
- `nodes.parquet` — 2 248 клиентов, колено обхода, признак seed;
- `transactions.parquet` — 4 840 отдельных переводов с датами.

Описание полей — `task/README.md`.

Внешний сервис один: **OpenAI Responses API**, только на экране «Ассистент». Модель выбирает детерминированные инструменты сервера и формулирует ответ. Роли, пороги, приоритет и числа она не считает и в выгрузки не пишет. Ключ `OPENAI_API_KEY` берётся из корневого `.env` (не коммитится), модель — `OPENAI_MODEL` (по умолчанию `gpt-5.6-sol`). Без ключа `POST /api/assistant/ask` отвечает 503; инструменты ассистента и остальной интерфейс работают локально.

## Ограничения

- Интерфейс показывает только результат пайплайна. Без выгрузки пайплайна экраны ролей, приоритетов и кластеров показывают ошибку, а схема сети — узлы без ролей.
- Активная выгрузка одна на сервер: переключение действует для всех, кто открыл интерфейс. Загруженные файлы на Railway лежат на диске контейнера и пропадают при передеплое; демо-выгрузка встроена в образ.
- Загрузка принимает только три `.parquet` со схемой `task/README.md`; выгрузку из транзакций и списка seed сервер не строит.
- Схема сети рисует все 2 248 узлов на canvas; раскладка считается на сервере при старте, примерно за секунду. На графе в ~1 млн узлов её нужно считать заранее и показывать фрагменты.
- Особенности данных, которые пайплайн должен учитывать: обрыв обхода на последнем колене (в данных организаторов — 4-е, 444 узла без исходящих — артефакт выгрузки), заниженные входящие у seed, порог 5 000 ₸, только исходящие и только внутрибанковские переводы.

## Deployed-версия

https://moneylai.up.railway.app — один сервис Railway, собирается из корневого `Dockerfile` (`railway.json`): образ `oven/bun` + `uv` с заранее собранным окружением пайплайна (Python 3.12, `uv sync --frozen`), `bun run build` для клиента; сервер отдаёт `/api` и `client/dist`, а загрузка выгрузки запускает пайплайн внутри контейнера без сети. Деплой из локальной копии: `railway up --service graf-deneg` (репозиторий организации не подключён к Railway, автодеплоя по push нет). Локальная проверка образа: `docker build -t graf-deneg . && docker run --rm -p 3001:3001 -e PORT=3001 graf-deneg`.
